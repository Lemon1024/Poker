# 德州扑克复盘工具执行计划 v1.2

2026-11-19。交付顺序为 **电脑离线 HTML → Android 权益 APK → 受限河牌 GTO**。实施使用[本地产品与计算接口](docs/LOCAL_PRODUCT.md)、[Android 交付规格](docs/ANDROID_DELIVERY.md)和[河牌模型规格](docs/GTO_RIVER_SPEC.md)。实际交付状态见[验收记录](../reports/STATUS.md)。

电脑端 H0–H4 已完成，包含手牌、公共牌与自定义范围组合的鼠标选牌和替换。用户已启动 Android 阶段，权益版和河牌策略升级版各有独立构建及验收记录。

## 一、电脑端要交付什么

用户解压文件夹后，双击 `index.html`，即可在断网的桌面 Chrome 或 Edge 中复盘。HTML、样式、脚本均随包交付，无需安装 Node、启动服务器或登录账户。界面使用简体中文，所有结果从持有自己底牌的一方看。

| 用户操作 | 页面反馈 |
| --- | --- |
| 输入自己和对手各两张具体底牌，比较翻前全下 | 显示自己赢、平、输的概率，标明「模拟估计」。 |
| 输入自己底牌和 3、4 或 5 张公共牌 | 默认对所有合法对手组合分析。每行显示对手底牌、当前领先／持平／落后、最终赢／平／输概率和权益；顶部汇总当前范围。 |
| 编辑具体组合及相对权重，筛选结果 | 先排除阻挡牌和零权重，再归一化。筛选只改变可见行，修改范围才改变总体概率。可按当前关系或最终权益筛选。 |
| 改牌、取消、保存、重新打开 | 改牌使旧结果失效，计算期间可取消；完成后可以在同一浏览器、相同文件位置重开保存的局面和结果。浏览器拒绝本地存储时，提示原因，仍可计算。 |

**展示约定。** 主要结果为赢、平、输三个百分比。权益作为单独指标，等于赢的概率加一半平局概率。页面和逐组合详情均省略模拟次数、枚举次数及整数胜负明细。河牌已发完时，每个固定对手组合只需比较牌力，显示「河牌已确定」；汇总仍随对手范围变化。

## 二、电脑端任务与多智能体分工

| 任务 | 负责人、依赖与文件边界 | 完成标准 |
| --- | --- | --- |
| H0 冻结接口 | 主智能体先行。维护接口说明、Worker 消息格式和集成入口。 | 固定两类输入、概率字段及单位、当前关系、方法标记、进度、错误和请求 ID。连接一个真实计算请求前先让三方使用同一组示例。 |
| H1 概率计算 | 计算智能体，依赖 H0。负责 `web/equity.js` 和相关计算模块。 | 实现合法发牌、牌力比较、范围加权与河牌直判。测试可注入随机种子。已有草稿由该智能体核查后决定复用哪些部分。 |
| H2 离线操作流程 | 界面智能体，依赖 H0。负责 HTML、CSS、界面脚本和历史记录。 | 先串起翻前输入到结果，再补翻后组合、范围、取消与历史。结果列表按需渲染；在文件协议下可打开所有本地资源。 |
| H3 独立验证 | 验证智能体，依赖 H0。独占测试目录和验收记录。 | 独立核对牌型、已有参考概率、范围边界及误差；准备真浏览器脚本。参考计算不调用生产牌力函数。 |
| H4 联调、交付 | 主智能体，依赖 H1–H3。负责实际 Worker 接线、版本清单与复测。 | 在桌面浏览器用真实文件、断网运行全部必测流程，提供可打开的入口和验收记录。通过后开放 Android 阶段。 |

H0 完成后并行派发 H1、H2、H3。每位智能体交回修改文件、实际验证命令、结果和剩余问题。共享接口由主智能体统一修改。阶段状态以实际证据更新；当前已有的内核草稿尚未验收。

## 三、概率计算与验收

- **抽样办法。** 翻前固定双方手牌，默认独立随机补足至少 100,000 个牌面。翻牌、转牌按对手组合分层抽样，每个组合默认至少 2,048 次，全部组合合计至少 100,000 次。每次发牌从剩余牌中无放回抽取；各组合结果按输入权重汇总。预算为初始工程值，可据实测调整并重跑同一套概率回归。
- **概率验收。** 测试固定三个预先选定的随机种子（1、42、2026）。用精确参考概率逐项检查赢、平、输，单个固定对局各项允许误差取五倍理论标准误或一个样本所占比例中的较大者。确定性结果必须完全一致。另用小型非等权范围逐行核对加权汇总。页面只在任务完成后发布结果。
- **三个必测局面。** ① `As Ah` 对 `Ks Kh` 的翻前参考概率依次约为 82.365%、0.544%、17.092%。② `As Ks` 对 `9c 9d`，翻牌 `2s 7s Td`，当前落后，最终赢率参考值约 55.05%，平局为零。③ `As Qs` 在 `Qd 8s 2s 7h 3c` 上对均匀范围，河牌汇总必须等于赢 884/990、平 6/990、输 100/990。用公共牌成皇家同花顺的局面检查平局 100%、权益 50%。这些分数仅用于测试。
- **输入和浏览器验收。** 覆盖重复牌、交换牌序的重复组合、空有效范围、被阻挡组合、零权重和非法权重。关闭网络并在干净的浏览器配置中双击页面，执行计算、筛选、快速改牌、取消、保存、关闭和重开。记录浏览器版本、场景耗时与控制台异常；检查运行期间没有外部资源请求。

## 四、后续阶段

1. **Android 权益 APK，依赖 H4。** 优先用 Android WebView 加载 APK 内置的同版页面与计算脚本，复用已通过的测试。先验证离线资源、Worker 和存储，再跑相同数学用例。在 Android 模拟器断网安装、计算、保存并重开后交付 APK，写明源码版本及所含架构。真机性能独立记录。仅当实测发现具体性能或兼容性问题时，再评估原生计算替换。
2. **河牌 GTO 主机工具。** 权益 APK 交付后，计算智能体实现 Kuhn Poker 基准及受限单挑河牌 CFR，验证智能体独立实现最佳响应，主智能体冻结策略接口。使用现有每方 8 个组合的基准，并增加同牌面非等权变体（先行动方首项 1/4、后行动方首项 1/2、其余为 1，合法配对总权重 407/8）。两组均需达到 `exploitability / root_pot ≤ 0.001`，记录范围、行动树、迭代数、误差与耗时。
3. **GTO 接入同一款 APK。** 主机验算通过后接入策略页，展示各行动频率、EV 和实际求解误差。用升级安装验证旧历史、原权益功能和两个策略基准。在目标设备实测后公布支持的范围规模。
